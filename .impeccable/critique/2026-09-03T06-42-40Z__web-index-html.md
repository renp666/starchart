## 1. 设计具体性判断：约 7.5/10

**是为本产品而做的，但骨架层接近通用 dashboard 模板。**

属于本产品的证据：

- emoji 微文案是全产品级习语：顶栏「⟳ 扫描」「🌳 树」与趋势区「🔥」「✨ 全部生成」「📋 速览」「📖 导读」同族，AI 动作统一用 ✨/📖
- AI 内容有专属视觉系统：`.tc-intro` 与 `.ai-wind` 共享「accent-soft 底 + 2px accent 左边线」，`renderAIBlock` 专为 LLM 中文行约定（`适合：/上手：/推荐：/本期风向：`）定制
- 产品使命长在 UI 里：🇨🇳 前缀、导读尾注「细节以仓库原文为准 + Zread 链接」、tr-note 写明 LLM 前置条件
- 恰当借用 GitHub 自身视觉语言：色点 + ★ + `+N`，对目标用户是加分

通用化的部分：两行 `.trend-ctl` 工具条无分组标签、无视觉分区；卡片流是标准 trending-list 模板。视觉语言（紫 accent、暗色、8px 圆角）连贯无问题，**问题在布局结构层**。

## 3. 认知负荷（8 项清单：失败 5、勉强 2、通过 1）

- ✗ **Single focus**：一屏平权承载 4 类任务（浏览/批量生成/速览/任意仓库解析），无分区
- △ **Chunking**：两行控件按「选榜单 vs AI 动作」分了行，但无组标题无分隔线，分行逻辑靠猜
- ✗ **Grouping**：第二行把批量生成、速览、adhoc（与榜单无关的低频功能）捆在一起
- ✗ **Visual hierarchy**：全局 `.hint` 无定义，`#tr-meta`/`.tr-note`/加载占位全以 13px 正文色渲染
- ✗ **One thing at a time**：guide(45vh)+digest(30vh)+进度条+列表可同屏全开，列表最坏被挤成 ~15vh
- ✗ **Minimal choices**：首屏 11 个交互控件（见下）
- △ **Working memory**：状态常驻且 UI 同步（好）；但切 since/lang 静默清空速览
- ✗ **Progressive disclosure**：唯一的低频功能（adhoc）永久占据第一屏；设置弹窗有 `details.advanced` 先例，这里没用

**首屏控件清点**：返回 1 + 第一行 6（seg×3 + 语言 + 过滤 + 刷新）+ 第二行 4（全部生成 + 速览 + adhoc 输入 + 导读按钮）= **11 个**；其中两个外观几乎相同的文本输入框上下相邻（filter 与 adhoc 都 `flex:1`，仅靠 placeholder 区分）。「全部生成」还是全屏唯一 `primary`——最重最贵的操作被标成视觉第一动作。

## 4. 情绪旅程

```
打开 → 加载 → 浏览 → 单卡生成 → 阅读导读
 疑惑   悬置   上升   ★深谷★    ★最深谷★
```

1. **打开**：顶栏 🔥 无文字无激活态；列表切入瞬间是一行纯文本「正在拉取…」，无骨架屏——「点了好像没反应」感
2. **单卡生成**：按钮变「…」并禁用，一次 LLM 调用最长 45s，无进度无 ETA 无取消；完成后 `trendRender()` 整表重绘，滚动/焦点复位小惊吓
3. **阅读导读（最深谷）**：导读插入列表**上方**的 `#tr-guide-box`——用户滚到第 10+ 张卡点按钮，导读出现在视口之外，无 scrollIntoView、无焦点移动、无提示。第一反应「点了没反应」，再点又等 45s
4. **批量生成**（支线）：进度+计数+停止+完成回拉+汇总 toast——掌控感良好，全面板情绪管理最好的一段

## 5. Persona 红旗

**Alex（效率型）**：🔴 无进入快捷键（只有 Esc能出）；🔴「全部生成」无视筛选，静默浪费 LLM 配额；🔴 Ctrl+K 聚焦的是项目树搜索，与当前任务无关；🟡 重生成无确认；🟡 批量无失败清单与单条重试。🟢 状态跨关闭保留、Enter 递交 adhoc、缓存/强刷区分。

**Sam（键盘/读屏）**：🔴 导读静默出现在视口外，无焦点移动、`#tr-guide-box` 无 role/aria；🔴 seg 无 `aria-pressed` 无 radiogroup 语义；🔴 异步占位直接 innerHTML 替换、无 aria-live；进度条无 `role="progressbar"`；🔴 `trendRender()` 整表重建，Tab 焦点跳回 body；🟡 ✕ 收起按钮命中区约 20px 且无 aria-label。🟢 全局 `:focus-visible` 存在、全真 button、外链带 `rel="noopener"`——`#toast`/`#detail` 都配了 aria，团队有这习惯，趋势视图漏了。

## 6. 优先问题（P0-P3）

### [P0] 导读「凭空生成」：结果出现在视口外

- **问题**：`showGuide()` 写入列表上方的 `#tr-guide-box`，浏览位置在列表深处时面板在视口外；无 scrollIntoView、无焦点移动、无 aria-live。单卡与 adhoc 两条路径都中招
- **为什么重要**：导读是面板招牌能力，「点了没反应 → 再点 → 再等 45s」是双倍成本的最差体验
- **修复**：最小改动——`showGuide` 末尾 `box.scrollIntoView({behavior:"smooth",block:"nearest"})` + 焦点移到收起按钮 + `role="region" aria-label="中文导读" aria-live="polite"`。结构性方案：导读/速览进右侧固定阅读栏（见 P1-2），从根上消灭「内容出现在别处」

### [P1] 大屏单列长卡片流：>1600px 空间利用率崩塌

- **问题**：平铺后独占 main 全宽，`.trend-list` 单列无 max-width——1920px 下每卡被拉到 ~1880px 宽；guide(45vh)+digest(30vh) 同开可吃 75vh，列表被挤成缝
- **修复**（成本递增三选一）：① 列表 `max-width:1400px; margin-inline:auto`；② ≥1400px 改 `grid; repeat(auto-fill, minmax(460px,1fr))` 双列紧凑卡；③ 左右两栏：左列表流、右固定阅读栏承接导读/速览（互斥 tab），列表永不被挤压，P0 顺势消解

### [P1] 控件区过载：11 件、两个孪生输入框、最贵按钮标成 primary

- **问题**：3 行 11 控件；`#tr-filter` 与 `#tr-adhoc` 外观相同且上下相邻，粘错无反馈；「✨ 全部生成」是唯一 primary；adhoc 低频却常驻第一屏
- **修复**：① 两输入框补 `#search` 同款样式（style.css L59-68 复制）+ adhoc 加 `aria-label`；② 收敛为一行核心（since+lang+filter+刷新），「全部生成/速览/adhoc」收进折叠区（`details.advanced` 有现成先例）；③ 至少加 11px 组标签「榜单」「AI 动作」

### [P1] `.hint` 在趋势视图内裸奔：状态文字与内容同权重

- **问题**：全局无 `.hint` 规则（仅 `.modal .hint`），`#tr-meta`/`.tr-note`/加载占位全以 13px 正文色渲染，与 h3 抢权重
- **修复**：加 `.hint { font-size:11px; color:var(--text-dim); }`；加载态升级为骨架卡片（复用 `.trend-card` 灰底）

### [P2] 批量范围与所见列表脱节 + 无障碍断链

- **问题**：`trendBatch` 以全量 `trend.items` 为目标，界面显示的是筛选后的 `shown`；seg 无 `aria-pressed`、进度条无 progressbar 语义、列表占位无 aria-live
- **修复**：有筛选时按钮文案动态化（「✨ 生成筛选结果（5）」）或点击时三选项确认；补齐 ARIA

## 7. 次要观察

1. `#btn-trending` 无激活态——面板开着时顶栏图标毫无变化，建议加 `.on`
2. 窄屏媒体查询不覆盖 `.trend-ctl`（无 `flex-wrap`），<900px 时 filter 被挤到不可用
3. digest 无法主动关闭，切周期时静默消失——建议加 ✕ 与过期提示
4. 趋势空态是一行字（树有空态插画+CTA，工艺不一致）；筛选无结果时给「清除过滤」按钮
5. 前 3 名无视觉强调——排名是趋势榜的核心叙事，可加 accent 描边或 ▲
6. `tc-name` 新标签页打开无预告（aria-label/title 补充）
7. `#tr-lang` 130px 定宽截断「Jupyter Notebook」，建议 `min-width:130px; flex:0 1 auto`
8. select 与按钮字号基线微跳（浏览器默认 ~13.3px vs 12px）
9. 「🔄 重生成」可加 title「将重新调用 LLM，覆盖现有介绍」
10. 单卡生成应对齐批量的状态标准（进度/ETA/可取消）

## 8. 值得思考的问题

- 如果导读和速览住进右侧阅读栏，「内容出现在别处」这一整类问题是不是就不存在了？
- 第一屏 11 个控件里，哪些每天用、哪些每月用一次？后者凭什么和前者同层？
- 「全部生成」到底应该作用于榜单还是当前筛选——用户的直觉答案是哪个？
