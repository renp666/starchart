## 3. 认知负荷（8 项清单：失败 5/8 —— 高负荷）

1. ✗ 单一焦点 — 浏览是主线，两条全宽工具条 + 持久顶栏（扫描/备份等无关控件）持续外围竞争
2. ✓ 分块 — 卡片内 head/desc/intro/actions 四分，≤4 动作组
3. ✗ 分组 — 两行 `.trend-ctl` 无容器边界/底色（`style.css:722–725`），是 2×4 同类矩阵；两个 `flex:1` 长输入框仅靠 placeholder 区分
4. ✗ 视觉层级 — `#tr-meta` 与 h3 同排同重；`.tr-note`、进度文字、空态均以正文色 13px 呈现（无全局 `.hint`）
5. ✗ 一次一事 — 两个同形输入框令用户在「过滤当前榜」与「解析任意仓库」间犹豫
6. ✗ 最小选择 — 面板内 11 控件（`#tr-back`1 + 行1 六件 + 行2 四件）；叠加仍可见顶栏 7 控件 + 每卡 1 链接 2–4 按钮 → 决策点远超 Cowan ≤4
7. ✓ 工作记忆 — 按钮随状态改名（✨→🔄、📖→看导读）是好的识别辅助
8. ✗ 渐进披露 — P2 级「速览 / ad-hoc」与 P0 级「时段×语言」同权平铺首屏

## 4. 情绪旅程

打开（缓存 <500ms，小峰）→ 撞上两行控制墙与同形输入框（微谷）→ 扫榜（平）→ 单卡「✨ 中文介绍」几秒内就地出紫色色条（**峰 1**）→ 「📋 本期速览」顶部插 30vh 灰框、列表被压短且**关不掉**（谷 1）→ 底部某卡点「📖 中文导读」等 10–45s 只见 "…"（谷 2）→ 结果出现在控制带正下方、列表整体下移、触发行可能滑出底缘、无任何焦点/播报（谷 3，最痛）→ 读到四段式中文导读（**峰 2**）→ Esc 干净返回。End 若停在无处可关的速览上则发涩。

## 5. 亮点

1. **缓存与降级的「内容永续」**（`1807–1843`）：榜单 30 分钟 + AI 结果长期 + stale 明确标注，重复打开成本≈0，诚实且少见。
2. **卡片单行信号压缩**（`style.css:761–773`）：排名/名称/语言/总星/本期增量一行扫完，`+N` 复用 sinceLabel 语义贯通。
3. **批次生成真实进度系统**（`1920–1956`）：进度+计数+失败+停止+指数退避，正是单条生成缺失的那套模型。

## 6. 优先问题

### [P1] 导读/速览结果 = 打断 + 零反馈（既有 P0 的机制修正）
- 几何核验：`#tr-guide-box` 在永不滚动的控制带正下方（`#trend-view` flex 列，overflow hidden），**始终位于视口内**——「结果出现在视口外」不成立；真问题是 `showGuide()`（`1907–1918`）无 scrollIntoView/无焦点移动/无 aria-live，随后 `trendRender()` 整表 innerHTML 重建（`1898`）把列表顶下移、触发按钮从 DOM 移除 → 触发行可能滑出底缘、键盘焦点坠回 body（B A7 证实：trend 块 0 处 focus/scrollIntoView）。
- 修复：生成期间给可感知进度（对齐批次模型）；结果出现 `scrollIntoView({block:"nearest"})` + 焦点 + `role="region" aria-label aria-live="polite"`；结构性解法见 §8(d) 右轨。
- 命令：`$impeccable layout`（+ `animate` 做过渡）

### [P1] 速览结果无法关闭
- `#tr-digest-box`（`index.html:118`，30vh）打开即无 ✕；唯一隐藏路径是切时段/语言或离开面板；与导读（45vh）同开可吃 ~75vh，列表剩 ~100–200px，浏览任务被堵死。
- 修复：头部加标题行（含日期/范围）+ ✕（复用 `#tr-guide-close` 模式 `1913,1917`），✕ 时 `box.classList.add("hidden")`。
- 命令：`$impeccable layout`

### [P1] 两条同构控制行 + 两个同形长输入框
- `#tr-filter`（过滤当前榜）与 `#tr-adhoc`（解析任意仓库，Enter 触发 AI）都占满剩余宽度、仅 placeholder 区分，输入后不可辨别 → 错位输入无即时反馈。
- 修复：`#tr-adhoc` 前置固定标签/图标并收窄；或收进「+」溢出菜单做渐进披露，首屏只留 时段×语言×刷新。
- 命令：`$impeccable distill`

### [P2] 布局：≥1600px 单列拉满全宽、无 max-width/断点
- `.trend-list`（`style.css:750–755`）单列无 max-width/分栏；`#trend-view` 独占 main 全宽（`711–716`）；唯一响应点是 ≤900px（`695`），1280–1920px 目标区间无宽度策略 → 行宽失控、右缘空置。方向建议见 §8(d)。
- 命令：`$impeccable adapt` / `layout`

### [P2] 全局 `.hint` 缺失，次要文本全以正文级呈现
- `#tr-meta`/`.tr-note`/进度文字/加载空态/导读脚注全部 `class="hint"`，全局仅有 `.modal .hint`（`371`）与 `.trend-progress .hint`（`796`）→ 回落 13px `--text`，与 h3/按钮抢权重；与弹窗/详情三套不一致。
- 修复：补全局 `.hint { font-size:11px; color:var(--text-dim); }`。
- 命令：`$impeccable layout`

### [P2] 批量范围与所见列表脱节 + 无障碍断链
- `trendBatch` targets=`trend.items` 全量（`1922`），忽略 `#tr-filter` 的 shown（`1850`），按钮文案不反映范围；B 证据：seg 无 radiogroup/aria-pressed、容器零 role/aria-live、进度条无 progressbar 语义、`#tr-filter`/`#tr-adhoc` 无 label、标题层级断裂（面板开启时唯一可见标题为 h3，无 h1/h2）、#btn-trending 无激活态。
- 修复：有筛选时按钮文案动态化（「生成筛选结果（N）」）或三选项确认；补 ARIA；面板标题升为 h2。
- 命令：`$impeccable harden`

**Riley（边界压力）**：榜单加载中过滤先渲染「暂无数据」再被覆盖（闪烁假错误）；ad-hoc 不剥 query 参数（`?tab=readme` 会随 fullName 送出）、不带协议粘贴解析错误；空结果无「清除过滤」；切时段静默丢弃已生成 digest。

## 8. 次要观察

- `.tr-note` 与 `#tr-meta` 缓存事实重复讲两遍；meta 显示「共 25 条」而非可见条数。
- 顶栏在趋势视图仍全功能：`#btn-view`（🌳 树）点击切换状态但树已隐藏=静默空操作；`#search` 作用于隐藏树。
- `closeTrending()` 只收 `#tr-guide-box` 不收 digest → 重开面板旧速览原样占首屏。
- `#btn-trending` 无激活态（无 `.on`/aria-pressed）。
- 连点两张卡的导读会并发多个请求，「最后返回者」覆盖导读框。
- 「📖 看导读」（已有缓存）仍无条件调后端 API（`1892`），离线本可本地直开。
- 单卡动作按钮约 22px 命中区（`style.css:781–784`），低于 24px 最小；`#tr-filter` 不支持 Esc 清空（`#search` 支持）。
- B 证据补充：`#tr-lang` 130px 定宽（`723`）闭合时截断 "Jupyter Notebook"；暗色 accent `#7c6cf2` 文字 on accent-soft 3.21:1、主按钮白字 3.97:1、tc-name b 3.85:1 均 <4.5 失败；亮色 warn `.tc-star` 3.83:1 失败；批量 `#tr-all` 双击存在窄窗双 POST（taskId 在 await 后赋值，`1929`）。

## 9. 值得思考的问题

1. 目标是「读懂」，为何 P2 级「解析任意仓库」与 P0 级「时段×语言」同层首屏，而不是把「本期速览」做成榜上头图、ad-hoc 收进溢出菜单？
2. 若导读出现在点击卡片附近（原位展开/右侧轨）而非顶部插入挤压整列，「卡片滑走、抬头找结果」的断层是否就消失了？
3. 最长 45s 且只有 "…"——对一个「点一下就读到中文」的面板，是进度表达问题，还是同步等待的交互模型本身需要重估？
