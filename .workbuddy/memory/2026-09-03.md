- 后端 server.py：新增 `fetch_trending`（抓取 github.com/trending，解析 Box-row 文章，缓存 30 分钟到 trend.json）、`gh_repo_meta`/`gh_readme`（raw README，ghToken 可配）、`trend_intro`（30 字中文一句话）、`trend_guide`（四段式中文导读：是什么/要点/适合谁/上手）、`trend_digest`（本期速览）、`trend_batch`（3 路并发批量介绍，可停止）、`llm_chat` 公共封装；路由 `/api/trending`、`/api/trending/intro|guide|intros(intros/stop)|digest`。
- 前端：顶栏 🔥 按钮打开趋势弹窗（时段/语言 seg 筛选、过滤、批量生成、速览、任意仓库导读、Zread 解读外链）；style.css 补齐 trend-* / tc-* / ai-* 全部样式；资源版本号 bump 到 20260903a。
- 验证：server.py 语法 OK、node --check OK、API 端到端 200（19 条榜单、缓存命中、intros/guides 持久化）。
- 坑：
  - GitHub trending 页描述 class 为 `tmp-pr-4`（GitHub 改版临时类），且 trending 页不含 topics；topics 需走 github api。

  - Windows 下 ThreadingHTTPServer allow_reuse_address 可致同端口双实例并存，旧托盘实例会截胡请求（本次 404 根因）；升级代码后必须 taskkill 旧 pythonw 实例。
  - agent-browser CLI 今天极不稳定（click/screenshot 持续 SIGTERM/挂起），只有后台 open 可用；UI 截图验证改用静态复核替代。

## zread.ai 探索功能底层逻辑调研结论

- zread.ai 为服务端渲染（SSR），trending/探索内容直接内嵌 HTML；未发现公开 JSON API；站点对自动化流量间歇性 504，HAR/请求捕获不稳定。
- 结论：其「探索」底层 API 不可公开获取。替代方案已落地：星图的「任意仓库中文导读」（等价于探索的按需解读）+ GitHub trending 抓取（等价于趋势面）。
