## 1. 背景与目标

星图是本地项目导航工具（扫描磁盘、建索引、跳转/启动项目）。用户同时是开源项目消费者，需要：

1. **发现**：不离开星图就能看到 GitHub 上正在流行的项目；
2. **读懂**：中文用户读英文 README 成本高，希望 AI 直接给出中文介绍与导读。

因此星图采用**同等用户价值的自研方案**：

- 趋势发现 → 抓取 github.com/trending 官方公开榜单；
- 按需解读 → 对任意 GitHub 仓库（不限于榜单）生成结构化中文导读。

## 2. 用户故事

- 作为开发者，我想按「今日/本周/本月 × 语言」浏览趋势榜，快速了解技术风向。
- 作为中文用户，我想一键看到某个趋势项目的**一句话中文介绍**，不用点进仓库。
- 作为中文用户，我想对榜单里的项目生成**中文导读**（是什么/要点/适合谁/怎么上手）。
- 作为评估者，我想让 AI **通读整份榜单**给出本期风向速览，而不是自己逐条看。
- 作为用户，我手头有任意 GitHub 仓库链接（哪怕不在榜单上），也想直接生成中文导读。

## 4. 非功能需求

- **性能**：榜单请求超时 25s；LLM 请求超时 45s；批量生成 3 路并发（对齐 AI 接口限流）。
- **安全**：仓库名只接受 `owner/repo` 正则，杜绝任意 URL 拼接；POST 有 Origin 校验；API Key 加密存储、接口返回打码（`********`）。
- **健壮性**：GitHub 页面改版导致解析为空时给出明确错误（「页面结构可能已改版」）；LLM 未配置时给出可操作的引导文案。
- **零依赖**：延续星图「纯 Python 标准库 + 原生 JS」架构，不引入第三方包。

## 5. 验收标准（v1 已全部通过）

1. 打开 🔥 面板 ≤3s 出现榜单（缓存命中时 <500ms）；
2. 19 张卡片字段完整渲染，无 JS 报错；
3. 语言下拉含 19 项（含「全部语言」），切换后重新拉取；
4. 批量生成可见进度并产生持久化结果（重启服务后仍在）；
5. 任意仓库链接粘贴可生成导读，输出符合四段式格式。

## 7. 名词表

- **榜单（list）**：某「时段×语言」组合下的 trending 条目集。
- **介绍（intro）**：单仓库 ≤30 字中文一句话，长期缓存。
- **导读（guide）**：单仓库四段式中文解读，长期缓存。
- **速览（digest）**：整份榜单的 AI 风向小结，按天缓存。
